# Response api_version

Part of the [service reference](../service.md).

The /range and /trend responses carry their own `api_version`, separate from the intake's: the one `declared-changes.json` holds. It moves once per release, in the release that changes what the responses offer. Each change lists the answers it adds, changes or removes in `declared-changes.json`, by its JSONPath (RFC 9535), and the release moves the version up by one and empties the list; CHANGELOG.md names each move. Up to "16", each move is also noted here. Version "15" is retired: the idle answer is redefined as the registered sprint span minus the sprint's session minutes, from the same session records that feed the working time (in whole minutes, in the sprint's registered timezone; a session belongs to the sprint label it was sent with, with no clamping to the registered span), so the working time and the idle time agree from the same session records; a sprint with no session records, or with no registered definition, reads null (no data, not zero); the span-window calculation no longer feeds the idle answer. Version "14" is retired: the cost answer (story_costs and cost) and the model-time split are redefined to be computed from the stories' session records (delivery sessions) instead of the finished-event cost payload; each story's cost is its model minutes in whole model minutes and its input and output tokens as whole counts from its delivery session records; the cost's total equals the sum of the story_costs entries; the model-time split's two parts read as planning and delivery, in whole model minutes; a new model_time answer carries the sprint's total model minutes and tokens across all session records (stories, planning, and card-less); a sprint with no session records reads null for cost, model_time, and model_time_split (no data, not zero); the finished-event cost payload stays accepted at intake but no longer feeds any answer. Version "13" is retired: working_time is redefined as the minutes of the sprint's session records (the stories' session minutes from each story's start on, plus the planning sessions' minutes, plus the card-less sessions' minutes, in whole minutes, with the displayed parts summing to the sprint's total) and the span-window calculation no longer feeds the working-time answer; a sprint with no session records reads null. Version "12" is retired: the sprint's planning part is added to /range (session_planning — the sessions that ran before their story's start, with their session minutes and model minutes, as a named part of the sprint's numbers against the delivery) and session_stories is redefined so that a story with session records but no delivery sessions reads a true zero (sessions ran, all of them are planning), distinct from the null of a story with no session record. Version "11" is retired: each sprint's per-story session-time answer is added to /range (session_stories — for each story whose sessions ran in the sprint, its session minutes in total and by role, its model minutes in whole model minutes, and its tokens as whole counts of input and output tokens; a story's numbers appear whether or not the story finished; a story with no session record reads null, never zero; a session counts in the sprint label it was sent with) and the `input_tokens` and `output_tokens` fields are added to the session event intake. Version "10" is retired: the `session` event is added to the intake (the crew's sessions as what happened — card (nullable), role, start, end, model time, tokens) and the session-time answers are added to /range and /trend. Version "9" is retired: each sprint's filed answer is added to /range (the filed-split answer — the total the crew filed, of which found by a role, from its own process, and split from already-filed work, beside what the Sponsor, the operator and anyone else filed; cards that can't be told apart reported as unknown, never guessed) and the `self_filed_share_percent` measure is added to /trend (the whole percent of the sprint's total filed cards that the crew filed, null where the sprint carries no filing facts). Version "8" is retired: each sprint's idle answer is added to /range (the idle time — the time that passed with no session running — against the sprint's total registered duration, in whole minutes) and the `idle_minutes` measure is added to /trend. Version "7" is retired: each sprint's model-time split answer is added to /range (the sprint's model time split into refinement and delivery, in whole minutes) and the `model_time_split_refinement_minutes` and `model_time_split_delivery_minutes` measures are added to /trend. Version "6" is retired: each sprint's cost-by-kind answer is added to /range (the sprint's working time split by story kind — addition and change — in whole minutes) and the `addition_working_time_minutes` and `change_working_time_minutes` measures are added to /trend. Version "5" is retired: each sprint's working-time answer is added to /range (the minutes the crew's sessions ran, per step of a story's pipeline, plus the sprint's working-time total) and the `working_time_minutes` measure is added to /trend. Version "4" is retired: the per-sprint roster (completed stories, released epics, achieved Goals by identifier) is added to /range and the window the response is judging is named (a top-level `window` object carrying the sprint labels at both ends, the sprint count, and which sprints had no data). Version "3" (release 3.0.0) is retired: 4.0.0 removed the escalation measures (`escalation_rate_percent` and `escalation_count` are gone from /range and its flags, and /trend refuses them). Version "2" was retired in 3.0.0 with the single-sprint answers (GET /sprint and GET /metrics now answer 410), and version "1" in 2.0.0, when /range gained `cost` and `story_costs` and `top_failure_causes` became a list of `{class, role, count}` entries. Event intake keeps its own version, "1".
