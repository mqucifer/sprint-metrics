# Stateful service

The stateful service accepts board events over HTTP and keeps their history in Postgres under its own schema. It answers range and trend queries from that history without the caller re-sending past data. The service is run from the released container image.

## Pages

The hand-written reference is a page per area, so a change to one area edits one page:

- [Running the service](service/running.md): starting it with `SPRINT_METRICS_DB`, and its automatic recovery.
- [Sprint registration](service/sprints.md): POST /sprints.
- [Event intake](service/events.md): POST /events and the board and session events it accepts (started, blocked, unblocked, finished, escalated, attempt_failed, superseded, returned, filed, and session), with their fields.
- [GET /range](service/range.md): the answer for a range of sprints, its window, verdicts and roster.
- [GET /trend](service/trend.md): one measure across sprints.
- [Response api_version](service/api-version.md): the /range and /trend responses' version and its history.
- [Error responses](service/errors.md): the 503, 500, 400 and 410 answers.
- [Telemetry](service/telemetry.md): the service's logs and traces over OTLP.

## Endpoints

The service exposes the following HTTP endpoints: POST /sprints for sprint registration, POST /events for event intake, GET /range for multi-sprint queries, GET /trend for time-series queries, GET /schema/event for the event schema, and GET /health for liveness checks.

Long-lived HTTP service that accepts board events and answers range and trend queries from Postgres.

| Method | Path | Description |
|---|---|---|
| POST | /sprints | Register or update a sprint definition (name, start date, end date, timezone). |
| POST | /events | Accept a board or session event (started, blocked, unblocked, finished, escalated, attempt_failed, superseded, returned, filed, session). The service validates the card's created date and event type. |
| GET | /range | Return metrics for a range of sprints in chronological order. Each entry includes the prior-sprint delta. failure_breakdown and top_failure_causes count returns, one per return, by (failure class, returning role). |
| GET | /range | The response carries a top-level window object naming the window it is judging: start (the first sprint label), end (the last sprint label), sprint_count (the number of sprints in the window), and no_data (the sprint labels that had no events). |
| GET | /range | The response also carries a verdicts object with one entry per registry measure: it judges the window's first and last data-bearing sprint (a gap sprint is skipped, not read as zero) against each measure's better direction — better, worse or flat, or up, down or flat for a measure with no better direction — each entry naming both reference sprints and their values, with the unit and the precision; an entry reads null when the measure's value is missing in either reference sprint, or the window has fewer than two data-bearing sprints. |
| GET | /range | Each entry also carries a cost answer: the per-story cost list (story_costs, each story's model minutes in whole model minutes and its input and output tokens as whole counts, from that story's delivery session records — sessions from the story's start on) and the sprint's cost middle and total (the median and sum of the three measures across stories that carry delivery session data). The cost's total equals the sum of the story_costs entries. A story's numbers appear whether or not the story finished. The six flat cost names (model_minutes_middle, model_minutes_total, input_tokens_middle, input_tokens_total, output_tokens_middle, output_tokens_total) appear on each entry's prior and delta. A sprint with no delivery session records reads null for cost and an empty story_costs list (no data, not zero). The finished-event cost payload (model_seconds and friends) is still accepted at intake but no longer feeds any answer. |
| GET | /range | Each entry also carries rework: two labeled parts — sent_backs (the stories sent back to the Business Analyst, its returned events, out of the stories started that sprint; each sent-back story is named by its identifier, and each send-back carries the step it was sent back from and the reason) and qa_returns (the review/QA returns, using the same (failure class, returning role) values as failure_breakdown; each returned story is named by its identifier, and each return carries the step it was returned from and the cause). A send-back counts in the sprint of the returned event. by_step groups each part's returns by step. Sprints with no events return all-null values, rework included. |
| GET | /range | Each entry also carries filed: the sprint's filed-split answer — the total the crew filed (crew_total), of which found by a role (found), from its own process (from_process), and split from already-filed work (split), beside what the Sponsor (sponsor), the operator (operator), and anyone else or cards with no known filer (other) filed; cards that can't be told apart are reported as unknown, never guessed. total_cards is the sprint's total filed cards; the buckets partition the sprint (crew_total = found + from_process + split + unknown, and crew_total + sponsor + operator + other = total_cards). self_filed_share carries the whole percent of the sprint's total cards that the crew filed, with its numerator (crew_total) and denominator (total_cards). A card counts in the sprint named on its 'filed' event (the sprint it was filed in), which may differ from the sprint where it merges. The filed answer is computed from the sprint's filed rows, independent of its delivery events: a sprint whose only stored rows are filed reads null for every delivery measure but still answers its filed split. A sprint with events but no filing facts reads filed null (no data, not zero); a sprint with filing facts in which the crew filed nothing reads the zero crew counts. |
| GET | /range | Each entry also carries a roster naming, by identifier, the stories that completed in that sprint, the epics that released in that sprint (an epic releases in the sprint where its last story's finished event is), and the Goals that were achieved in that sprint (a Goal is achieved in the sprint where its last epic releases). Sprints whose stories carry no epic or goal link read null for the corresponding roster part (no backfill). |
| GET | /range | Each entry also carries a dora block: the sprint's release frequency (how often epics actually ship) and lead time for changes (the mean, in whole days, of each released story's span from its creation to its epic's release moment); a sprint whose finished events carry no epic link reads null for both, not zero. |
| GET | /range | Each entry also carries a working_time answer: the sprint's working time — the minutes of the sprint's session records, in whole minutes. The stories' session minutes (from each story's start on), the planning sessions' minutes (before their story's start), and the card-less sessions' minutes (no story) sum to the sprint's total. A session belongs to the sprint label it was sent with, with no clamping to the registered span. A sprint with no session records reads null (no data, not zero). |
| GET | /range | Each entry also carries a cost_by_kind answer: the sprint's working time split by story kind (addition and change), in whole minutes; a sprint whose stored story rows carry no kind reads null (no data, not zero). |
| GET | /range | Each entry also carries a model_time_split answer: the sprint's model time split into planning and delivery, in whole model minutes, from the session records. The planning part is the model minutes of sessions that ran before their story's start; the delivery part is the model minutes of sessions from the story's start on. A sprint with no carded session records reads null (no data, not zero). |
| GET | /range | Each entry also carries a model_time answer: the sprint's total model time across all session records (stories, planning, and card-less sessions), in whole model minutes and whole token counts. A sprint with no session records reads null (no data, not zero). |
| GET | /range | Each entry also carries an idle answer: the sprint's idle time — the registered sprint span minus the sprint's session minutes, from the same session records that feed the working time, in whole minutes, in the sprint's registered timezone (a session belongs to the sprint label it was sent with, with no clamping to the registered span; the span-window calculation no longer feeds the idle answer); a sprint with no session records, or with no registered definition, reads null (no data, not zero). |
| GET | /range | Each entry also carries session_stories: the sprint's per-story session-time answer — for each story whose sessions ran in the sprint, its session minutes in total (session_minutes, whole minutes), its minutes by role (minutes_by_role, roles named with the crew's role strings), its model minutes (model_minutes, whole model minutes), and its tokens (input_tokens and output_tokens, whole counts). A story's numbers appear whether or not the story finished. A story with no session record reads null (unknown), never zero. A story with session records but no delivery sessions (no 'started' board event, or sessions all before the story's start) reads a true zero: sessions ran, all of them are planning. A session counts in the sprint label it was sent with, unclamped to the sprint's registered span. Each entry also carries session_planning: the sprint's planning part — the sessions that ran before their story's start, with their session minutes (session_minutes, whole minutes) and model minutes (model_minutes, whole model minutes), as a named part of the sprint's numbers against the delivery (the stories' sessions from their starts on). A story with session records but no 'started' board event has no established start, and its sessions read as planning until one is stored. A card-less session is never planning-or-delivery-of-a-story: it counts in the sprint's numbers only. A sprint with no carded session records reads session_planning null. |
| GET | /range | Each entry also carries session_epics: the sprint's per-epic session-time answer — for each epic whose stories had sessions in the sprint, its in-sprint session minutes in total (session_minutes, whole minutes), its minutes by role (minutes_by_role, roles named with the crew's role strings), its model minutes (model_minutes, whole model minutes), and its tokens (input_tokens and output_tokens, whole counts), summed over that sprint's stories of the epic. An epic whose stories carried no session record in the sprint reads unknown (null) for its in-sprint total, never zero: session_minutes, minutes_by_role, model_minutes, input_tokens and output_tokens are all null, and the entry lists the unknown stories beside the total (their count in unknown_story_count and their identifiers in unknown_stories). Where only some of the epic's stories have session records, the in-sprint total covers only the stories with records, and the entry lists the unknown stories beside the total. A story whose board rows carry no epic link contributes to no epic's total; its sessions still appear in the per-story answer. A card-less session belongs to no epic. Each entry also carries session_epics_to_date: the sprint's per-epic to-date session-time answer — for each epic whose stories had sessions in any sprint up to and including this one, the same measures (session_minutes in whole minutes, minutes by role, model_minutes in whole model minutes, input_tokens and output_tokens as whole counts) accumulated across every sprint to date, with gap sprints bridged and not read as zero. An epic whose stories have no session record in any sprint up to and including the current one reads unknown (null) for its to-date total, never zero; the entry lists the unknown stories beside the total. A gap sprint with no sessions for the epic carries the prior to-date total forward. A story whose board rows carry no epic link contributes to no epic's to-date total; a card-less session belongs to no epic. |
| GET | /trend | Return a single metric across a sprint range. Returns a JSON object with api_version and an ordered sequence of sprint-label-to-value pairs (the values array). Valid metrics: cycle_time_days, lead_time_days, throughput, wip_violations, blocked_aging_days, first_attempt_rate_percent, points_delivered, first_attempt_numerator, first_attempt_denominator, superseded_count, superseded_points, superseded_breakdown, cycle_time_minutes, lead_time_minutes, model_minutes_middle, model_minutes_total, input_tokens_middle, input_tokens_total, output_tokens_middle, output_tokens_total, cached_input_percent, reasoning_output_percent, sent_backs_count, release_frequency, dora_lead_time_days, change_failure_count, change_failure_rate_percent, mean_time_to_recovery_minutes, working_time_minutes, addition_working_time_minutes, change_working_time_minutes, model_time_split_refinement_minutes, model_time_split_delivery_minutes, idle_minutes, self_filed_share_percent. Minute-based metrics (cycle_time_minutes, lead_time_minutes) return JSON integer values in minutes (rounded); sprints with no events return JSON null. working_time_minutes returns the sprint's working-time total in whole minutes (null where the sprint has no session records). addition_working_time_minutes and change_working_time_minutes return the sprint's working time for stories of the given kind in whole minutes (null where the sprint carries no kind data). model_time_split_refinement_minutes and model_time_split_delivery_minutes return the sprint's model time split into planning and delivery, in whole minutes (null where no story in the sprint carries a split). release_frequency returns the sprint's count of distinct epics released, in releases per sprint. dora_lead_time_days returns the mean lead time for changes, in whole days. change_failure_count and change_failure_rate_percent return the sprint's change-failure rate in whole percent (the rate is shown alongside its count). mean_time_to_recovery_minutes returns the mean time to recovery, in whole minutes. A sprint without a derivable DORA value (no events, or no epic link, or no epic release for the change-failure and recovery measures) returns JSON null. idle_minutes returns the sprint's idle time — the registered sprint span minus the sprint's session minutes, from the same session records that feed the working time — in whole minutes, in the sprint's registered timezone (null where the sprint has no session records or no registered definition). self_filed_share_percent returns the whole percent of the sprint's filed cards that the crew filed itself. Its unit is a percent of the sprint's filed cards: the crew-filed count out of the total-filed count, the unknown cards included in the total. The counts behind each value live in the sprint's per-sprint filed split in the /range answer (the total the crew filed, of which found, from its own process, and split from something already filed, beside the Sponsor's, the operator's and anyone else's filings, and the unknown cards). A card counts in the sprint it was filed in, not the sprint it merged. A null value means the sprint holds no filing facts (no data — the service never answers 0 or 100 for a fact-less sprint, and null is not 'no self-filed work'); a 0 is a different, true answer: the sprint's stored facts show the crew filed none of the cards filed in that sprint. |
| GET | /schema/event | Return the JSON Schema for the event intake body. |
| GET | /health | Health check. Returns 200 with {"status": "ok"} when the database is reachable, 503 otherwise. |
